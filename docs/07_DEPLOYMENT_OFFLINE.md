# 07 部署与离线交付

## 1. 支持边界

- Windows：Conda/Python 应用，FastAPI 提供本机页面和 API；不要求 Docker，不要求 Node.js 运行时。
- Linux：Docker Worker；不安装 Web 管理端，也不要求浏览器访问。
- 两个平台的核心 Engine 源码一致；平台依赖锁定并分别准备离线依赖。
- 第一阶段安装、升级、任务 ZIP 和结果 ZIP 可经组织批准的离线介质/堡垒机传递。
- Python 版本基线为 3.11+；精确 patch 版本、Windows 版本、Linux 发行版、CPU 架构及 Docker Engine 版本待运维确认。

## 2. 交付物建议

### Windows 离线交付

- Conda 环境规格或可离线导入的环境包；包含锁定版本的 Python 运行依赖。
- AI-PERF 后端发行包与前端已编译静态资源。
- 初始化、启动、停止、升级、健康检查和备份脚本/说明。
- 数据目录及日志目录说明；不得默认写进安装程序目录或当前工作目录。
- SBOM/依赖清单和 SHA-256 校验文件。

### Linux Worker 交付

- 按目标 Linux 架构预构建的 Docker 镜像归档文件。
- Worker CLI、任务/结果 Schema、依赖锁和镜像摘要。
- 只读输入目录、可写工作目录和输出目录说明。
- 导入任务、检查 Worker、运行任务、查看日志、导出结果的 CLI 手册。
- Worker 版本/Engine 版本/协议兼容矩阵及离线升级/回滚说明。

真实项目依赖版本、镜像仓库地址和目标发行版目前没有资料，不在此文档填入未经验证的具体版本号。

## 3. Windows 安装/启动流程建议

1. 验证安装包哈希与来源。
2. 在批准路径创建应用目录、数据目录、日志目录和临时目录。
3. 离线创建/导入 Conda 环境；依赖安装使用锁定清单，禁止安装时隐式访问公网。
4. 运行配置初始化，明确监听地址、端口、数据路径和备份路径。
5. 初始化/迁移 SQLite；迁移失败时保留原库并报告恢复方法。
6. 运行健康检查；验证静态资源、数据库写入、目录权限和版本兼容。
7. 默认只在 `127.0.0.1` 提供 Web 服务；开机自启方式由运维环境确认。

可用 `conda-lock`、wheelhouse 或经验证的 Conda 包缓存实现离线依赖，但具体工具由构建环境决定。安装包不得把 secret 直接写入明文配置样例。

## 4. Linux Docker Worker 流程建议

1. 用 SHA-256/签名验证镜像归档来源，导入 Docker。
2. 创建专用非特权运行账户和受限工作目录。
3. 挂载只读任务输入、本地秘密文件/秘密 provider 和可写输出目录；秘密权限仅 Worker 可读。
4. 使用只接受明确命令的 Worker CLI 验证包、预览任务摘要、运行任务和导出结果。
5. 先运行健康检查和空载兼容性检查，不连接 Windows 管理端。
6. 任务完成后确认结果包校验，再通过批准的堡垒机流程取回。
7. 依组织保留策略清理临时解包目录；保留 Run 状态和结果至结果包确认交付。

容器是否可完全断网、是否允许访问 DNS/代理、是否要挂载 CA 证书由目标内网策略决定。Worker 需要访问被授权的目标 API，因此不能在未讨论网络需求时设置一个会阻断目标访问的通用网络策略。

## 5. 运行配置和路径

所有路径由显式应用配置解析，不能依赖工作目录。建议分开：

- `data_dir`：SQLite、数据集元数据；
- `assets_dir`：附件原始字节；
- `runs_dir`：执行明细、导出报告；
- `packages_dir`：待传任务包和导入结果包；
- `temp_dir`：临时上传、解压和构建文件；
- `log_dir`：结构化日志。

Windows 路径需测试空格、中文、UNC/网络路径策略、盘符和反斜杠。是否允许网络共享路径待确认。Linux 容器路径使用 POSIX 规范，文件权限及 UID/GID 映射必须写入安装说明。

## 6. 升级、回滚和备份

- 应用和 Schema 分开版本化；启动时先检测支持的数据库版本，再执行事务化迁移。
- 升级前备份 Windows SQLite 和必要文件；恢复演练是验收项。
- 任务 ZIP 不是 SQLite 备份；数据库备份必须包含元数据一致性和关联附件策略。
- 回滚应恢复匹配版本的应用、数据库副本和静态资源，不能只替换程序文件。
- Worker 镜像升级不应删除挂载卷中的历史 Run 和结果。
- 升级前拒绝运行中的不兼容数据库迁移，除非实现明确支持并测过在线迁移。
- 备份频率、保留周期、RPO/RTO 和数据清理策略由业务/运维确认。

## 7. 离线依赖构建与供应链

- Windows 和 Linux 分别生成、校验依赖锁文件，避免把不同平台轮子混用。
- 依赖解析在联网的受控构建环境完成，最终安装包需记录源、版本、哈希和许可证清单。
- 运行环境启动和任务执行不要求公网依赖下载。
- Vue 构建只发生在开发/构建环境；发布静态文件，不在 Windows 运行时调用 npm。
- Docker 镜像使用明确版本和摘要；禁止 `latest` 作为可复现发布标识。
- 发布物附带 SHA-256；若内网供应链要求签名，增加签名验证流程（待确认）。

## 8. 运维检查

建议提供以下本地诊断命令/页面：应用版本、Schema 版本、Python 版本、目录可写检查、磁盘空间、SQLite 可读写检查、静态资源状态、Worker/Engine/协议兼容、最近错误摘要。诊断不得显示密钥或完整敏感请求。

## 9. 待确认

1. Windows Server/桌面版本、Conda 发行版和 Python 精确版本。
2. Linux 发行版、架构、Docker 版本、是否 rootless。
3. 是否能运行 Docker，是否需要容器镜像离线导入。
4. TLS CA、代理、DNS 和 Worker 出网策略。
5. 数据盘大小、备份位置、RPO/RTO 和保留周期。
6. 依赖包签名、SBOM、许可证审核和制品来源要求。
