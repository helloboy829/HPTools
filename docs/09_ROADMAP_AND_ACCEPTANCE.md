# 09 路线图与验收标准

## 1. 目的和状态

本文件把 `docs/AGENTS.md` 的建议开发顺序细化为可交付阶段和验收门槛。阶段中的验收是工程基线建议；业务规模、目标环境和安全制度相关的数值需在 M0 评审时确认。阶段完成不能只以页面可打开或 HTTP 200 作为证据。

## 2. 阶段交付

### M0：需求基线和风险关闭

**交付：** 文档清单、术语表、明确约束/建议基线/待确认项、源工作簿样例和目标环境信息清单、架构/ER/包 Schema 初稿、功能优先级、验收责任人。

**退出条件：** P0 安全、数据、执行语义和协议问题已确认或明确标记为实现阻塞项；不存在被误称为已确认的临时决定；所有专题文档可在仓库定位。

### M1：可运行基础骨架

**交付：** Python 3.11+ 包结构、配置和应用根路径、结构化日志/脱敏、错误码、基础领域模型、依赖锁、测试入口。

**验收：** 在 Windows 测试中文路径、空格和反斜杠；运行不依赖当前工作目录；UTC 序列化可往返；秘密字段脱敏测试通过；Engine 包不导入 FastAPI。

### M2：请求定义与 cURL 导入

**交付：** 请求/步骤模型、JSON/表单/文本/multipart 请求构建、受限 cURL 解析草稿、业务校验模型。

**验收：** 支持样例请求可被本地 mock server 捕获并与预期 method/header/body 对比；cURL 命令注入样例不会执行；无法支持的选项给出诊断；请求 schema 校验拒绝缺失/非法字段。

### M3：数据集、附件和映射

**交付：** 已确认格式的导入、版本、预览、字段映射、附件存储和流式读取。

**验收：** 错误能定位到行/字段；大文件不整体读入内存；中文文件名、重复名和跨平台路径可处理；附件哈希可验证；越界路径拒绝；历史 DatasetVersion 不被修改覆盖。

### M4：统一核心 Engine

**交付：** 固定并发执行、超时/取消、错误分类、逐请求结果、聚合指标和 Run 状态机。

**验收：** 服务端拒绝 concurrency=0 和 >100；同时在途事务不超过设置值；逻辑事务数可核对；传输/HTTP/业务错误区分正确；取消后不再派发新任务；超时和失败不会丢失已完成结果；统计边界符合冻结公式。

### M5：校验、结果模型与报告

**交付：** 版本化结果 Schema、校验结果、统计摘要、分页明细、报告数据模型。

**验收：** HTTP 成功但规则失败时业务成功为 false；percentile/成功率对固定测试向量结果符合定义；空样本和未完成 Run 有确定展示；报告不含秘密和默认完整响应正文。

### M6：Windows 管理端

**交付：** FastAPI、SQLite、Vue3 静态构建资源、环境/请求/数据/任务页面、本机运行、状态查询和取消。

**验收：** 可按用户旅程创建任务并查看结果；后端限制能阻止恶意客户端提交 >100 并发；断开 WebSocket 不影响执行；服务重启后历史记录按批准的恢复目标可见；Windows 运行不需要 Docker/Node.js 运行时。

### M7：标准包协议和 CLI

**交付：** 版本化 Schema、任务包导出/校验、结果包导入、CLI、人工传输操作说明。

**验收：** 合法测试包可 round-trip；修改任一文件可被散列校验发现；Zip Slip、超限 ZIP、重复路径、大小写碰撞和未知主版本被拒绝；重复导入按协议幂等；包中无秘密。

### M8：Linux Docker Worker

**交付：** 独立 Worker CLI、容器镜像、挂载目录、秘密引用、本地状态/结果、结果包导出。

**验收：** Worker 不启动 Web 管理端且无 Windows 回连；隔离网络下能执行批准目标；Windows 关机后任务仍运行；容器停止后已持久化数据存在；任务状态、Engine/Worker 版本及结果可被 Windows 导入。

### M9：离线交付和跨平台验收

**交付：** Windows 离线包、Linux 镜像归档、依赖锁和哈希/SBOM、安装升级/回滚/备份说明、签署验收记录。

**验收：** 在无公网环境从干净机器安装；启动、导入、执行和结果导出不拉取在线依赖；Windows 和 Linux 同一 Engine 构建标识一致；备份恢复演练通过；依赖与安全扫描问题有处理结论。

### 后续阶段：自动传输

仅在堡垒机支持方式、MFA/审批、凭据保管、命令限制和审计均有明确方案后单独立项。不得作为首期 Worker 运行的依赖。

## 3. 验收测试矩阵

| 测试层 | 覆盖内容 | 通过证据 |
|---|---|---|
| 单元测试 | 模型、变量、指标公式、状态机、错误分类、Schema | 固定测试向量和明确断言 |
| 请求构建集成 | JSON、表单、文本、multipart、多文件、工作流变量 | Mock HTTP 服务收到的请求与预期一致 |
| 数据文件集成 | CSV/JSON/JSONL/XLSX（按批准清单）、附件引用和流式处理 | 规范化导入结果、行数、哈希、内存/流行为记录 |
| 管理 API 集成 | 校验、创建任务、启动/查询/取消、分页 | HTTP 输入输出和持久化状态匹配 |
| 包协议测试 | task/result 正常包和损坏/攻击样例 | 对照 Schema、校验错误码和 round-trip 结果 |
| Worker 集成 | 离线解包、秘密缺失、执行、状态落盘、导出 | 容器日志、挂载文件和导入后结果 |
| 跨平台测试 | Windows 与目标 Linux 上路径、请求模型、Engine、统计 | 两端相同协议样例与固定指标向量一致 |
| 安全测试 | 脱敏、路径穿越、ZIP 炸弹、cURL 注入、目标校验 | 所有恶意样例被阻止且无目标请求发出 |
| 运维测试 | 离线安装、升级、回滚、备份恢复、磁盘不足 | 按手册记录的完整演练结果 |

具体性能压力测试本身也需要定量门槛，但当前没有目标硬件、API 响应规模和期望吞吐数据，因此暂不填任意数值。

## 4. 首期发布门槛

首期发布前至少满足：

1. 产品和安全 P0 待确认项有负责人结论。
2. 固定并发执行语义、指标公式和错误分类冻结。
3. Windows 本机执行与 Linux Worker 确认复用同一核心版本。
4. ZIP 输入校验、路径防护、包版本和重复导入行为稳定。
5. 所有秘密/敏感字段日志测试通过。
6. Windows 与 Linux 离线安装均已在干净环境实际验证。
7. 备份恢复、Worker 中断和结果包回传完成演练。
8. 用户手册说明目标授权、人工堡垒机传输和结果解释方式。

## 6. 变更管理

- 架构约束的修改需同步更新 `docs/README.md`、`docs/AGENTS.md`、相关专题规格和迁移/验收计划。
- 数据/包 Schema 变化必须提升版本或提供兼容迁移，不能只改文档字段。
- 对“建议基线”的正式决定记录批准人/日期/理由；被否决的选项不继续作为运行行为。
- 新增 P0 要求时应同步评估里程碑、风险和验收测试。

## 7. 待确认

1. 每阶段是否需要业务签字，签字人和验收环境是什么。
2. 性能验收使用的硬件、目标 API、并发、运行时和误差范围。
3. 跨平台结果可比性的允许差异和 Engine 版本锁定策略。
4. 数据保留、备份恢复、停机恢复的目标数值。
