# 08 安全与可靠性

## 1. 安全目标和威胁边界

AI-PERF 会向用户指定服务发送压力请求，并处理可能包含业务数据、凭据和文件的配置与结果。重点保护对象包括：API Token/密码、请求头、上传文件、数据集、请求/响应内容、任务 ZIP、错误日志、Windows 本地数据库和 Linux Worker 挂载目录。

威胁来源包括误配置、恶意或损坏的 ZIP/数据文件、非授权目标、同机其他用户、日志/备份泄露、路径穿越、cURL 命令注入和 Worker 网络访问被滥用。内网部署不等于可信输入或无访问控制。

## 2. 凭据处理

- 真实密钥不得存入任务 ZIP、普通配置导出、日志、错误明细或报告。
- API/UI 只显示秘密是否已设置和安全引用名称；保存时不得回显原值。
- 日志默认脱敏 Authorization、Cookie、Token、Secret、密码、签名及按配置标记的敏感字段。
- 任务模型存 `credential_ref`，执行时由平台凭据 provider 注入内存。
- Windows 和 Linux 的秘密存储独立；Linux Worker 的本地秘密不得由任务包覆盖。
- cURL 导入遇到疑似秘密值应遮盖并要求建立秘密引用。
- 错误信息、变量展开异常、WebSocket 事件、导出报告和 crash dump 均纳入脱敏检查。
- 环境变量可作为一种 provider，但不应在诊断或全环境导出中打印全部变量。

**待确认：** Windows Secret Store/DPAPI/受控本地文件等具体 provider；Linux 使用受限权限文件、容器 secrets 或组织秘密系统；秘密轮换和多人共享策略。

## 3. 目标授权、地址校验与 SSRF

压力测试产生真实负载，必须明确目标和授权。

- 用户显式输入目标 URL，并在启动前看到完整 scheme/host/port、并发、请求数及数据集。
- 保存确认时间、操作者（如无账号则记录本机使用主体/明确说明）、目标摘要和授权引用（若组织提供工单号）。
- 不提供网段扫描、自动发现目标或未经用户确认的自动重定向目标。
- 校验允许的 scheme（建议 HTTPS/HTTP 按部署策略配置）、端口、主机名及 DNS 解析结果；目标解析/重绑定和代理行为须定义。
- 默认不跟随跨主机重定向；若允许，重定向后的 host 必须重新验证授权。
- 内网私有地址是合法产品场景，不得无差别禁止所有私网地址；应使用显式 host/IP/port 授权策略。
- 连通性检查与性能测试分开标注，且连通性检查应限制为单次/低频请求。
- 对所有 API、CLI、导入任务包路径执行同样目标校验，不能只依赖前端确认。

具体授权范围（精确主机、网段、端口、DNS 变化、代理、HTTP 明文是否允许）由部署方确认。

## 4. 文件与路径安全

- 上传流式写入临时文件，限制文件数、单文件和总大小，完成格式和哈希校验后原子提交。
- 不使用用户文件名作为存储路径；展示名仅做安全转义。
- 所有内部路径经 `pathlib.Path.resolve()` 或等价规范化后确认仍在受控根目录。
- 拒绝绝对路径、盘符/UNC、`..`、符号链接逃逸、设备文件和不支持的特殊文件。
- 解析 Excel 时不执行宏、公式或外部链接；只读单元格值，公式策略显式化。
- ZIP 防护包括 Zip Slip、符号链接、大小写冲突、重复路径、压缩炸弹、超大目录和声明不一致。
- 临时目录权限最小化，清理策略明确；清理失败应记录非敏感诊断。
- 对 HTML/CSV 报告输出做转义，防止响应文本注入脚本或表格公式注入。

## 5. cURL 和请求执行安全

- cURL 解析器不得调用 Shell；禁用命令替换、管道、重定向、外部配置文件和代理命令。
- 用户提供的模板不执行 Python、JavaScript、模板表达式之外的任意代码。
- 变量插值采用受限语法；拒绝文件系统路径或环境变量的任意读取能力。
- 每个请求限制超时、并发和响应读取量；默认不自动重试有副作用的方法。
- 禁止将响应正文、异常对象或请求对象直接完整序列化进日志。
- 代理、证书验证关闭和跨主机重定向等安全敏感选项需显式配置、警告并记录。

## 6. Web/API 安全

- 默认只监听 loopback；如开放 LAN，先落实认证、会话保护、CSRF、CORS、TLS、授权和审计。
- 不信任客户端传来的 Task 状态、并发限制或结果指标；服务器端重新验证。
- 上传接口设置大小和速率限制；导入/删除等状态变更需要授权和 CSRF 保护（若使用 Cookie 会话）。
- 错误响应不返回堆栈、秘密、绝对路径或环境变量。
- 静态页面使用严格资源策略；输出用户提供的 HTML/文本时转义。
- SQLite 数据目录按本机账户最小权限保护；备份文件同样按敏感数据管理。

## 7. 结果和隐私

- 结果默认保存统计值、状态码、错误类别和有限诊断，不保存完整请求/响应正文。
- 若业务确需样本正文，使用字段白名单、截断、脱敏、访问控制、保留期限和导出提示。
- 报告标识数据集版本和附件摘要，避免不必要地复制原始个人/业务数据。
- 数据删除必须处理关联的附件、临时文件和导出包；备份中的删除时效按备份策略说明。
- 导出 ZIP 前显示文件清单、大小和敏感数据提示，确保仅包含当前任务引用数据。

## 8. 可靠性和恢复

- 每条结果以追加或事务方式持久化；汇总可重建，避免只有内存里的唯一结果。
- SQLite 开启并验证合适的事务、外键和备份行为；精确 WAL/同步参数通过可靠性测试决定。
- Worker 在任务开始前将状态写为 running，并周期性追加结果/进度快照。
- SIGTERM/容器停止时停止新派发、收尾在途请求、flush 文件并标记 `interrupted` 或 `cancelled`。
- 启动时扫描不完整 Run 和临时导入；不得无提示地将不确定状态改成成功。
- 结果包导入采用暂存与事务，避免部分导入；重复导入按 package ID 幂等。
- 文件句柄、aiohttp Session/Connector、锁和临时目录均要有清晰关闭责任。
- 异常分类后进入结果或系统诊断；禁止吞异常。

## 9. 日志与审计

建议结构化字段：`timestamp_utc`、`level`、`event`、`request_id`、`task_id`、`run_id`、`step_id`、`error_code`、`duration_ms`。禁止记录 secret value、未经脱敏的 Authorization/Cookie、全量环境变量、任意完整响应正文。

审计事件至少考虑：目标授权确认、任务启动/取消、任务包导出、结果包导入、秘密引用变化、配置和数据库迁移。是否需要用户身份、不可抵赖存储和远程日志系统待确认。

## 10. 必需安全测试

- 日志与报告中对 Authorization、Cookie、Token、密码、签名的脱敏测试。
- cURL Shell 注入样例不执行且被拒绝/安全解析。
- 路径穿越、UNC/盘符、Unicode 规范化和符号链接逃逸测试。
- ZIP 炸弹/超限、哈希错误、重复文件、大小写碰撞、未知 schema 测试。
- 缺失 Linux secret 时在网络请求前失败。
- 未确认目标和跨主机重定向按策略阻止。
- 大附件、多并发和取消时文件句柄/内存使用受限。
- HTML/CSV 报告转义和响应字段脱敏测试。

## 11. 待确认

1. 组织目标授权方式、审计字段和授权有效期。
2. 两端凭据 provider、权限、轮换和密码恢复方案。
3. 是否允许明文 HTTP、关闭 TLS 验证、代理和重定向。
4. 响应样本、日志和附件保留周期及数据分级要求。
5. 访问控制、备份加密、签名包和安全事件处置要求。
