# 01 产品需求规格

## 1. 文档状态

- 状态：详细需求草案，供评审后冻结为基线。
- 依据：当前 `docs/README.md`、`docs/AGENTS.md`、`docs/CODEX_FIRST_PROMPT.md`。
- 标记规则：**明确要求**表示现有材料已经确定；**建议基线**表示为补全规格提出的默认方案；**待确认**表示需要业务/运维负责人给出答案。
- 当前没有随仓库提供的源 Excel 或运行环境清单；涉及源清单字段和环境限制的内容均不得假定已核实。

## 2. 产品概述

AI-PERF 面向可由用户明确配置和授权的内网 AI API / AI 组件，支持管理请求定义和数据集、以受控并发发送请求、检查配置的业务成功条件、记录性能结果，并生成可复核的报告。Windows 提供唯一 Web 管理端及本机执行能力；Linux 通过独立 Docker Worker 离线执行从 Windows 导入的任务包。

### 2.1 目标

1. 让测试人员通过配置而不是为每个用例编写专用脚本来定义测试。
2. 支持 JSON、文本、表单、multipart、多文件及多步骤 API 场景，特别保留真实文件上传行为。
3. 用统一 Engine 和结果 Schema 保证 Windows 与 Linux 执行结果可比。
4. 适配隔离或受限内网：首期用人工堡垒机传递标准任务 ZIP/结果 ZIP。
5. 使执行目标、并发、凭据、错误和结果都可审计、可复核。

### 2.2 非目标

- 首期不自动理解模型答案的语义正确性，不默认提供 LLM-as-a-judge、OCR 或语义评分。
- 不扫描网段、探测未知目标或默认对未授权目标压测。
- 不把 Linux 做成 Web 管理端或依赖 Windows 在线的远程 Agent。
- 不以任务 ZIP 代替 SQLite 备份。
- 首期不要求实时回传 Linux 任务状态；Linux 任务本地查看日志，完成后回传结果包。
- 首期不要求自动 SSH/SFTP 或绕过堡垒机 MFA/审批。
- 不承诺通用 API 编排器、任意 Shell 执行器或任意 Python 插件运行环境。

## 3. 用户与使用场景

### 3.1 用户角色

| 角色 | 主要工作 | 状态 |
|---|---|---|
| 测试执行者 | 配置目标、请求、数据集和任务，启动测试，查看和导出结果 | 产品必需角色；是否需要账号体系待确认 |
| 平台维护者 | 安装升级、备份数据、配置 Worker 镜像和本地凭据 | 产品必需的运维职责；可与测试执行者由同一人承担 |
| 结果审阅者 | 查看任务结果、对比执行、导出报告 | 是否需要只读角色待确认 |

**建议基线：** 第一版只实现本机单管理员使用，不加入多租户、复杂 RBAC 或远程用户管理。若 Web 绑定非 loopback 地址，则必须另行落实认证与访问控制后才能开放。

### 3.2 用户旅程

#### Windows 本机执行

1. 维护 API 环境和凭据引用。
2. 导入或创建请求定义，配置变量、文件和校验规则。
3. 导入数据集并预览字段、行数和文件关联。
4. 创建任务，选择请求/工作流、数据集、请求数、并发和超时。
5. 阅读目标授权提示，确认目标和执行参数。
6. 启动任务，观察运行状态与聚合进度。
7. 查看错误分类、性能统计、逐请求结果和校验失败样本。
8. 保存执行记录并导出报告。

#### Linux 离线执行

1. Windows 对任务配置、目标地址、数据集、文件和 Linux 凭据引用做导出前校验。
2. 生成不可变任务快照和任务 ZIP。
3. 用户通过组织批准的堡垒机人工上传 ZIP。
4. Worker 校验包、版本、散列、路径和目标配置；在本地确认秘密已配置。
5. Worker 独立运行并将日志、状态和请求结果写入挂载目录。
6. Worker 生成结果 ZIP。
7. 用户经堡垒机下载；Windows 验证并导入结果。
8. 报告显示执行端、Engine 版本、任务快照和导入来源。

## 4. 功能需求

优先级：P0 为首期不可缺少；P1 为首期可选或增强；P2 为后续。

| 编号 | 优先级 | 需求 | 验收方向 |
|---|---|---|---|
| FR-001 | P0 | 管理 API 环境、目标地址和非秘密配置 | 创建、修改、删除、校验并留有稳定 ID |
| FR-002 | P0 | 凭据通过本机安全引用注入 | 普通配置导出、包、日志、报告均无秘密值 |
| FR-003 | P0 | 创建/编辑 HTTP 请求和多步工作流 | 支持方法、URL、参数、头、超时、请求体及步骤顺序 |
| FR-004 | P0 | 导入 cURL 并转换为请求草稿 | 仅解析数据，不执行 Shell、子命令或脚本 |
| FR-005 | P0 | 导入数据集并预览、校验和映射 | 错误可定位到文件/行/字段；导入不静默丢数据 |
| FR-006 | P0 | 通过真实流式文件上传执行 multipart 请求 | 支持图片、PDF、Excel 和多个文件，不先替换成抽取文本 |
| FR-007 | P0 | 配置请求数、并发、超时和数据选择方式 | 服务端模型验证并拒绝超出硬限制的值 |
| FR-008 | P0 | Windows 本机运行测试 | 记录任务生命周期、聚合进度和每请求结果 |
| FR-009 | P0 | 配置业务成功条件 | HTTP 状态与业务规则分开统计 |
| FR-010 | P0 | 生成可复核的指标和错误详情 | 指标口径统一，敏感响应内容默认不写入结果 |
| FR-011 | P0 | 导出 Linux 任务 ZIP | 导出前校验；任务快照固定；无明文凭据 |
| FR-012 | P0 | Linux Worker 离线校验和执行任务包 | 不依赖 Windows 服务或共享数据库 |
| FR-013 | P0 | Worker 生成结果 ZIP 并在 Windows 导入 | 验证版本、关联 ID、散列和路径；保留导入记录 |
| FR-014 | P0 | 对危险配置和未知目标显示确认 | 用户需明确确认目标及授权；不执行网络扫描 |
| FR-015 | P0 | 对并发做服务端硬限制 | 默认 100；有效值需在 1..100，除非后续正式批准新上限 |
| FR-016 | P0 | 管理任务历史、状态和报告 | 能区分配置任务和执行实例 |
| FR-017 | P1 | WebSocket 展示 Windows 本机任务进度 | 断连后可重连并获取当前快照；不影响 Engine 执行 |
| FR-018 | P1 | 比较多次执行 | 比较相同指标口径，并标示不兼容 Engine/Schema 版本 |
| FR-019 | P1 | 记录人工核验字段 | 用户可在结果中补充复核状态或备注 |
| FR-020 | P2 | 自动 SSH/SFTP 传输 | 独立阶段，需满足审批/MFA/审计要求 |

## 5. 数据处理和结果原则

- 每次执行基于不可变的任务快照，之后修改模板不应改变历史执行解释。
- 结果至少区分传输错误、超时、HTTP 不合格、业务校验失败、取消和内部错误。
- HTTP 2xx 不是业务成功的充分条件；用户可配置校验规则。
- 响应正文默认不持久化；确需保存时需配置大小上限和脱敏策略（待确认）。
- 数据集和附件需可追踪到来源及版本；文件采用流式读取和上传。
- 任务包中不得有真实凭据；Linux Worker 的秘密由 Linux 本机运维配置。
- 报告注明目标、执行端、任务快照、Engine/协议版本、开始结束时间、并发与数据集摘要。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 跨平台 | Python 3.11+；路径由应用配置解析；UTF-8；Windows 中文、空格和反斜杠路径可用 |
| 性能 | 并发不超过 100；请求发送采用异步 I/O；文件以流方式处理。吞吐目标与数据规模待确认 |
| 可重复性 | 同一 Engine 版本、配置、数据快照和目标条件下，产生结构兼容且统计口径一致的结果 |
| 可靠性 | 临时文件、会话、连接器和数据库事务有明确生命周期；错误可追踪；Worker 中断后保留已写入结果 |
| 安全 | 默认 loopback 管理端；凭据脱敏；目标授权；上传/ZIP 校验；路径穿越防护 |
| 可维护性 | Engine 不依赖 FastAPI；外部输入用 Pydantic 或等价模型校验；依赖锁定 |
| 可部署性 | Windows Conda 离线运行；Linux Docker Worker 离线运行；运行时无公网要求 |
| 可观测性 | 结构化日志、统一错误码和任务状态；不得记录秘密或任意完整敏感响应 |
| 可用性 | 管理端本地重启后可读取历史任务和结果；Worker 可从挂载目录导出已有结果 |

具体吞吐、数据集规模、文件大小、保留周期和恢复时间目标均待确认，不在本规格中虚构数值。

## 7. 首期范围边界

**纳入：** 单机 Windows Web 管理、请求/数据集配置、本机 Engine、ZIP 导入导出、Linux Docker Worker、离线依赖和验收。

**暂不纳入：** 多租户、云端 SaaS、实时 Linux 监控、自动化堡垒机传输、语义质量评判、自动网段发现、分布式调度集群。

## 8. 术语

| 术语 | 定义 |
|---|---|
| 请求定义 | 可重复使用的 API 请求配置或有序多步骤流程 |
| 数据集行 | 单次执行使用的一组变量和文件引用 |
| 任务 | 用户配置的执行计划；执行时生成不可变快照 |
| 执行实例（Run） | 某个执行端对特定任务快照的一次具体运行 |
| 事务 | 对单步请求等同一次请求；对多步流程是完成一组步骤的一次业务用例，最终口径待评审 |
| Worker | Linux Docker 中的离线任务校验和执行程序，不是远程常驻 Agent |
| 任务包/结果包 | 分别用于跨端传递执行输入和执行输出的版本化 ZIP 文件 |

## 9. 待确认清单

1. 是否需要账号、认证和多角色权限；管理端是否可能开放给 loopback 之外的主机。
2. 固定请求数之外，是否需要固定时长、固定 RPS 或阶梯加压模式。
3. 测试数据最大规模、文件大小和结果保留周期。
4. 业务成功条件表达式的范围、响应字段提取语法和正则能力。
5. 报告导出格式、是否允许保存响应正文及脱敏要求。
6. 源《AI组件测试对象清单》的真实格式、字段和授权信息。
7. 吞吐、可用性和任务恢复的量化验收目标。
